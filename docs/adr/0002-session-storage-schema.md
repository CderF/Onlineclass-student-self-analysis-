# 决策记录：课程记录的存储结构（SQLite）

## 2026-10-26　课程记录存入本地 SQLite，按「听课时间轴」每秒一条

**状态**：已采纳

### 背景

需求见 `docs/self-analysis-requirements.md`：边记录边写入、崩溃时保留已记录部分、支持暂停、只存数值、需要 CSV 导出和多节课汇总。表结构一旦有了真实实验数据就很难再改，因此先定下来。术语见 `GLOSSARY.md`。

### 决策

1. **文件**：`data/self_analysis.db`（相对仓库根目录，已加入 `.gitignore`）。用 `PRAGMA user_version` 记录表结构版本，当前为 1。开启 WAL 模式，每秒数据写入后立即提交，崩溃最多丢失最后约 1 秒。每个连接显式开启 `PRAGMA secure_delete`；删除课程记录后执行 `wal_checkpoint(TRUNCATE)`，被删数据不会残留在主库的空闲空间或 WAL 中（#17）。
2. **时间轴**：所有 `t` 都是**听课时间轴**上的秒数——从校准结束开始计 0，暂停期间不前进，继续后接着往下数。另存墙上时间（Unix 秒）供与外部问卷对齐。校准期（前 3 秒）不记录。**暂停点**取暂停前最后一帧的听课时间 `t`；它所在的那一秒已写成一条样本（不足一秒也写），继续时从**下一秒**（`floor(t) + 1`）开始，时间轴按构造连续、不重复（2026-11-04 修订，#15：原为暂停时刻向上取整，最后一帧到暂停之间跨过整秒时会缺一秒）。
   - 继续后，记录器在第一帧处理完时才启动（以该帧时刻为起点），等待摄像头首帧的时间计入暂停，不算听课时间。
   - 请求暂停 / 终了之后才读到的帧不处理、不记录。
   - 一帧都没有的采集段（如校准刚结束就暂停）不写暂停记录。
3. **四张表**：

| 表 | 一行代表 | 主要列 |
|---|---|---|
| `sessions` | 一条课程记录 | `id`、`course_name`（Stop 后填写，可为空）、`started_at`、`ended_at`、`status`（`recording` / `completed` / `interrupted`）、`baseline_pitch`、`baseline_yaw` |
| `samples` | 听课时间轴上的 1 秒 | `session_id`、`t`（整数秒，与 `session_id` 组成主键）、`wall_time`、`score`、`fatigue_index`、`cognitive_state`、`spatial_state`、`face_ratio`、`delta_pitch`、`delta_yaw`、`frame_count` |
| `events` | 一个事件 | `id`、`session_id`、`kind`（`spatial` 空间状态区间 / `alert` 警报）、`type`（空间状态代码或警报类型）、`t_start`、`t_end`（警报与 `t_start` 相同；进行中为空）、`wall_start` |
| `pauses` | 一次暂停 | `session_id`、`t`（暂停前最后一帧的听课时间）、`paused_at`（按下暂停的墙上时间）、`resumed_at`（继续后首帧的墙上时间；未继续为空） |

4. **每秒汇总规则**：
   - 参与度分数、疲劳指数：该秒内各帧平均。
   - 认知状态：该秒众数（并列时取该秒内先出现的）；该秒全部为空（无脸或无表情结果）则记空。
   - 空间状态：该秒最后一帧。
   - `face_ratio`：该秒内检测到人脸的帧占比；`delta_pitch` / `delta_yaw`：该秒内有值帧的平均，无值则为空。
5. **事件**：空间状态从 `normal` 变为其他代码时开一个 `spatial` 事件，变回或变成另一个代码时关闭，精度为帧级（`t` 为浮点秒）。警报按分析器实际发出的时刻记 `alert` 事件。暂停或结束时，进行中的事件止于最后一帧。
6. **课程记录状态**：Start 后摄像头首次成功打开时插入 `recording`（摄像头打不开不留空记录）；校准结束时写入校准基准并开始记录；Stop 或关闭窗口时改为 `completed`（关闭窗口属于正常退出，课程名可事后在管理功能里补）。程序启动时仍为 `recording` 的记录视为崩溃遗留，改为 `interrupted`（这一检查只在拿到单实例锁之后进行，#13：同一数据库只能有一个程序实例，再次启动时调出已开的窗口后退出，因此不会把正在运行的实例的记录误判为遗留）：`ended_at` 取最后一条样本的墙上时间，未关闭的事件在最后一条样本的末尾（`t + 1`）关闭。**一秒数据都没有的记录**（如校准期内就终了）在结束或启动检查时直接删除，不询问课程名。
7. **实现**：`app/session_store.py`（建表、记录状态）与 `app/session_recorder.py`（`SessionRecorder`，一次采集一个实例）。
8. **线程**：写库在 `CameraThread.run()` 内进行，每次 `run()`（包括暂停后继续）自己打开和关闭连接，不跨线程共享连接。Stop 后填写课程名、删除、改名等管理操作在界面线程用独立连接完成。

### 理由

- 听课时间轴让「课的第几分钟」在有暂停时仍然连续，问题时段和多节课对比都直接用它。
- 每秒一条在一节 90 分钟的课上约 5400 行，查询和导出都很轻；帧级原始数据不保存（需求已确认）。
- 空间状态区间按帧级单独存为事件，比从每秒样本反推更准，也省去报告端重复计算。

### 未采纳的方案

| 方案 | 未采纳原因 |
|---|---|
| 每节课一个 JSON / CSV 文件 | 多节课汇总要遍历文件；崩溃时文件可能写坏 |
| 用墙上时间作为唯一时间轴 | 暂停会在曲线上留下空洞，「第几分钟」与课程内容对不上 |
| 共享一个跨线程连接（`check_same_thread=False`） | 需要自己加锁；每次 `run()` 独立连接更简单 |

### 何时需要重新评估

- 需要保存帧级原始特征来事后重算公式。
- 实验改为在受试者电脑上运行，需要合并多台机器的数据库。
